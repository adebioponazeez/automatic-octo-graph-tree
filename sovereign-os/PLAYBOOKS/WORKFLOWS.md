# PLAYBOOK: WORKFLOWS — v30

> The four production workflows from Section 6 of the v30 document.

## Workflow A — New initiative (default)

1. Update State Pack first. **If you skip this, stop.**
2. STRATEGIC:
```
OS v30. State Pack below.

STATE PACK:
[paste]

New initiative: [one sentence]
Constraints: [time, money, stack, audience, sovereignty]
Current assets: [list]
Produce: governing principles (max 7), 90-day done, trade-off map, Mermaid system map, cheapest test, irreversible mistakes, exact files to write into the canonical store.
```
3. User accepts or amends principles. Write them into `PRINCIPLES.md` and `DECISIONS.md`.
4. SOFTWARE and/or PRODUCT-CONTENT with the accepted strategy only.
5. CRITIC on the package.
6. User accepts.
7. OPS turns it into SOP + checklist + freeze conditions.
8. Write artifacts into the store the same day.

## Workflow B — Daily production (survival cadence)

Human time box: 25 minutes. See `CHECKLISTS/DAILY-CHEAT-SHEET.md`.

## Workflow C — Weekly audit

Every week, 40 minutes, to CRITIC then OPS.
See `AUDITS/WEEKLY-AUDIT-TEMPLATE.md` and `CHECKLISTS/WEEKLY-AUDIT-CHECKLIST.md`.

## Workflow D — Existing messy setups

To STRATEGIC:
```
OS v30. I have existing prompts/tools:
[paste or describe]

Goal: convert them into specialized v30 operators with no overlap, external source of truth, and 7-year survival.
Do not flatter the current setup.
Produce: target architecture, what to kill, what to keep, exact prompt changes, and the first 7 days of migration.
```
See `../COMPARE-v30-vs-EXISTING.md` for the current migration plan.
